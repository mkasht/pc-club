# План разработки сайта по методичке

Дата подготовки: 26 октября 2026 года.

План основан на документе «Metodichka (1).docx», включая встроенные примеры кода, и на предоставленном скриншоте итоговых требований. На момент составления плана в папке были только требования и инструкция. Текущее состояние реализации приведено ниже.

Цель первой версии — работающее приложение на C# и ASP.NET Core MVC с каталогом услуг, страницей контактов, регистрацией, входом, защищённой панелью администратора и собственным API. Для реализации выбрана тематика компьютерного клуба и визуальное направление по предоставленному пользователем референсу invasion.ru. PcClub / PC CLUB — рабочее название; реальные контакты и материалы клуба пока не предоставлены.

## Что входит в первую версию

- Главная страница с информацией о компании или клубе.
- Список услуг и отдельная страница каждой услуги.
- Категории услуг и типы Standard и VIP, как в примере документа.
- Контактная информация из настроек приложения.
- Регистрация обычного пользователя, вход и выход.
- Роли User и Admin, отдельный доступ администратора.
- Добавление, просмотр, изменение и удаление категорий и услуг.
- Загрузка изображения услуги.
- Хранение данных в SQL Server через Entity Framework Core.
- Вывод категорий и услуг из базы на страницах сайта.
- Связь один ко многим между категорией и услугами.
- Собственный API каталога с ответами JSON.
- Применение ООП с примерами, которые можно объяснить на защите.
- Журнал событий и ошибок через Serilog.

Онлайн-бронирование компьютеров, оплата, личный кабинет посетителя, учёт игровых сеансов и управление клиентскими компьютерами в методичке не описаны. Если они нужны, их следует отдельно спроектировать после базовой версии. Для бронирования понадобятся дополнительные сущности, правила занятости и защита от одновременного резервирования одного места.

Твои действия: подтвердить тематику, название, контакты и срок. Обязательные функции уже зафиксированы по скриншоту. Если есть дополнительные условия преподавателя, добавить их к этим требованиям. Уточнить, обязательно ли начинать с пустого шаблона и сохранять структуру файлов из примеров. Перед реализацией API проверить, достаточно ли собственного API чтения каталога.

Моя помощь: превратить требования в перечень страниц и функций, отметить обязательные пункты и дополнительные пожелания. Для компьютерного клуба предложить категории и примеры услуг без выдуманных цен и характеристик.

Результат: короткое техническое задание и согласованный перечень функций первой версии.

### 2 Подготовить рабочее окружение

Твои действия: при необходимости выполнить системные действия, которые требуют прав администратора, и выбрать удобный редактор. Пароли вводить локально, не отправляя их в переписку.

Моя помощь: проверить соединение с SQL Server, определить имя сервера, настроить локальный инструмент dotnet-ef в проекте и объяснить сообщения об ошибках. Если SQL Server не запускается, сначала выяснить причину и только затем решать вопрос установки или восстановления.

Результат: доступны сборка проекта, команды EF и подключение к учебной базе данных. Не использовать рабочую базу с чужими данными.

### 3 Создать каркас приложения

Моя работа: создать проект, организовать папки Controllers, Views, Models, Domain, Infrastructure и wwwroot; подключить MVC, маршруты, статические файлы и настройки. Добавить журналирование, файл исключений для Git и инструкцию запуска. Если требуется строгая последовательность методички, использовать пустой ASP.NET Core шаблон и подключить MVC вручную.

Твоя работа: открыть проект, запустить его вместе со мной и разобраться, как запрос попадает в контроллер и затем в представление Razor.

Проверка: проект собирается, главная страница открывается локально, стили загружаются, остановка и повторный запуск проходят без ошибок.

Моя работа: подготовить или адаптировать согласованный HTML-макет, вынести шапку, подвал и подключения стилей в общие представления. Создать главную страницу, меню и контакты. Предусмотреть мобильную ширину экрана.

Твоя работа: предоставить или утвердить название, тексты, контакты и изображения. Если используется сторонний шаблон, проверить условия его использования и требования к указанию автора.

### 5 Спроектировать данные и создать базу

Моя работа: создать сущности EntityBase, ServiceCategory и Service; перечисление типов услуг; AppDbContext с поддержкой Identity. Явно настроить связь один ко многим: у категории коллекция Services, у услуги внешний ключ ServiceCategoryId и ссылка на категорию. Настроить ограничения и первую миграцию. Отключить каскадное удаление категории вместе с услугами. Подготовить несколько согласованных демонстрационных записей, включая минимум две услуги одной категории.

Минимальные поля услуги: идентификатор, название, дата создания, краткое и полное описание, изображение, тип услуги и необязательная категория. Цена и длительность тарифа — отдельное дополнение, если сайт клуба должен их показывать: в приведённой модели их нет.

Твоя работа: проверить, что категории и услуги соответствуют заданию, посмотреть созданные таблицы и понять их связь.

Проверка: миграция создаёт базу и внешний ключ, одна категория связана с несколькими услугами, данные сохраняются после перезапуска приложения, удаление используемой категории не удаляет услуги.

Моя работа: реализовать интерфейсы репозиториев и их реализации EF, DataManager и регистрацию зависимостей, как предусмотрено методичкой. Создать DTO и модели форм, чтобы публичные страницы и редактирование получали только нужные поля. Дату создания и другие служебные значения определять на сервере.

Отдельно разобрать ООП: наследование сущностей от EntityBase; инкапсуляцию доступа к данным за методами и закрытыми полями зависимостей; абстракцию через интерфейсы репозиториев; полиморфизм при вызове конкретной EF-реализации через интерфейс, переданный в конструктор. Для каждого понятия подготовить объяснение на реальном участке проекта.

Твоя работа: разобрать один путь целиком — чтение услуги из базы, преобразование данных и отображение на странице.

Проверка: списки и отдельные записи читаются из базы; отсутствующая запись обрабатывается корректно; связанные категории подгружаются.

### 7 Реализовать регистрацию вход и роли

Моя работа: настроить Identity, роли User и Admin, первоначальное создание администратора через UserManager и RoleManager. Создать RegisterViewModel и форму регистрации с логином или email, паролем и подтверждением пароля. Добавить проверку повторного логина или email, форму входа и выход. Новому пользователю назначать только роль User на сервере; не принимать роль из формы. Администратора создавать отдельной первоначальной инициализацией. Использовать одинаковые имена ролей во всех местах. Закрыть административные действия проверкой прав и защитить изменяющие запросы от подделки.

Твоя работа: выбрать локальные данные доступа, зарегистрировать обычного пользователя и проверить вход, выход, ошибки регистрации и сообщение при неверном пароле.

Проверка: регистрация создаёт пользователя в базе; повторные данные и несовпадающие пароли дают понятную ошибку; пароль хранится в виде хеша средствами Identity; посетитель без входа не открывает административные страницы; обычный пользователь не получает права администратора, в том числе при подмене полей запроса; после выхода редактирование недоступно; адрес возврата после входа проверяется как локальный.

### 8 Сделать управление категориями и услугами

Моя работа: создать список записей и формы добавления, изменения и удаления. При необходимости сохранить partial AdminController из методички. Добавить проверку обязательных полей, выбор категории и типа, понятные сообщения об ошибках и подтверждение удаления.

Сначала завершить весь сценарий для категорий, затем повторить его для услуг. Категорию с привязанными услугами не удалять: показать объяснение и предложить сначала изменить категории услуг.

Твоя работа: самостоятельно добавить категорию и услугу, изменить описание, проверить удаление и ошибки заполнения.

Проверка: все операции отражаются в базе и публичном каталоге; отправка неправильных данных не приводит к сохранению; несуществующий идентификатор обрабатывается без падения.

### 9 Добавить изображения и полные описания

Моя работа: сделать загрузку картинок с ограничением размера, проверкой расширения и фактического содержимого, безопасным новым именем файла и обработкой ошибок. Организовать отдельное место хранения и отображение по контролируемому пути. Предусмотреть отсутствие картинки и замену изображения.

Форматированный редактор описаний подключать после работы обычного текстового поля. Если используется TinyMCE, сначала проверить условия выбранного варианта подключения. HTML очищать на сервере по разрешённому набору тегов до вывода без экранирования.

Твоя работа: проверить загрузку подходящей картинки, неподходящего файла, слишком большого файла и замену старого изображения.

Проверка: одинаковые исходные имена не перезаписывают чужие картинки, запрещённые файлы отклоняются, вставленный в описание скрипт не выполняется.

### 10 Завершить публичный каталог

Моя работа: подключить список услуг, карточку услуги, динамическое меню, страницу контактов, пустые состояния и страницу 404. Проверить внешний вид на компьютере и телефоне.

Твоя работа: наполнить каталог реальными или явно демонстрационными данными и пройти сайт как посетитель.

Проверка: новая услуга после сохранения видна посетителю, изменения сразу отражаются в карточке, отсутствующая услуга возвращает 404, отсутствие категории или картинки не ломает страницу.

### 11 Реализовать API каталога

Моя работа: создать отдельный контроллер API, возвращающий DTO в JSON, и подключить его маршруты. Использовать общий доступ к данным с MVC-контроллерами, чтобы сайт и API работали с одной базой.

Минимальный набор запросов:

- `GET /api/services` — список услуг.
- `GET /api/services/{id}` — одна услуга, ответ 404 при отсутствии.
- `GET /api/categories` — список категорий.
- `GET /api/services?categoryId=1` — услуги выбранной категории.

Публично отдавать только данные каталога. Не включать пользователей, пароли, настройки и секреты. Административное изменение данных в первой версии выполнять через защищённую панель. Если требуется CRUD API, отдельно добавить защищённые операции записи и проверки доступа.

Твоя работа: выполнить подготовленные HTTP-запросы и объяснить отличие HTML-страницы от ответа JSON. Для сдачи сохранить примеры запросов в файле `.http` или другом удобном формате.

Проверка: список и карточка возвращают JSON и статус 200; несуществующая услуга возвращает 404; фильтр показывает услуги нужной категории; изменения из админки видны и на сайте, и в API.

### 12 Проверить проект и подготовить передачу

Моя работа: проверить сборку и основные сценарии; добавить содержательные автоматические проверки регистрации и прав, сохранения данных, удаления связанной категории, обработки загрузок и ответов API. Проверить журналирование без паролей и секретов. Подготовить README с восстановлением зависимостей, созданием базы и запуском приложения.

Для учебной сдачи подготовить описание архитектуры, схему базы, сценарий демонстрации и объяснение основных файлов. Скриншоты делать с реально работающего приложения.

Сценарий защиты: открыть главную, каталог и контакты; зарегистрироваться и войти обычным пользователем; показать отсутствие доступа к админке; войти администратором; создать категорию и две услуги в ней; показать их в каталоге и через API; объяснить внешний ключ и примеры ООП; перезапустить приложение и показать сохранённые данные. Проверить каждый пункт таблицы требований в начале плана.

Твоя работа: запустить проект по инструкции и продемонстрировать полный сценарий самостоятельно.

Проверка: проект можно развернуть из исходников на чистой учебной базе; инструкции соответствуют реальным действиям; основные функции понятны тебе без подсказок.

### 13 Опубликовать сайт если это требуется

Публикация — отдельный этап после локальной проверки. Выбрать площадку с поддержкой ASP.NET Core и доступной SQL Server, настроить HTTPS, отдельные секреты окружения, постоянное хранение изображений и резервное копирование. Условия и стоимость площадки проверить перед выбором.

Моя помощь: собрать приложение для публикации, подготовить настройки и инструкцию развёртывания, проверить доступность и основные сценарии после запуска.

Твоя часть: выбрать и при необходимости оплатить площадку и домен, предоставить доступ через доступный безопасный способ и утвердить публикацию конкретного готового результата.

Проверка: сайт работает по внешнему адресу, вход защищён, картинки сохраняются после обновления приложения, есть проверенный порядок восстановления данных.

## Исправления к методичке

1. Visual Studio 2022 и .NET 10 не составляют поддерживаемое сочетание для разработки под net10.0. Выбрать совместимый Visual Studio 2026 или VS Code с .NET CLI.
2. В командах использовать обычные двойные дефисы: `dotnet --version`, `dotnet ef --version`. Исправить `mirgations` на `migrations`.
3. Привести к единым названиям Login и UserName, Photo и PhotoFileName, ShortDescription и DescriptionShort, а также регистр роли admin и Admin. Текст и скриншоты используют разные варианты.
4. Для локальной базы предпочесть проверку подлинности Windows, если она доступна. Не копировать строку с `sa` и паролем `sa`. Секреты хранить в User Secrets или переменных окружения.
5. Не создавать хеш пароля заново внутри HasData при построении модели. Использовать отдельную первоначальную инициализацию администратора через Identity. Показанное подавление PendingModelChangesWarning не использовать как замену исправлению причин рассогласования модели и миграции.
6. Не завершать сеанс действием GET при открытии страницы входа. Выход выполнять отдельным защищённым POST-запросом.
7. Не перенаправлять на произвольный returnUrl. Проверять локальность адреса и предусмотреть безопасную страницу по умолчанию.
8. Не сохранять файл напрямую по `file.FileName`. Генерировать имя на сервере, проверять размер и содержимое, ограничивать доступ к хранилищу.
9. Не выводить произвольный HTML через Html.Raw без серверной очистки. Доверие к администратору само по себе не заменяет обработку содержимого.
10. Использовать отдельные модели входных форм; не принимать из браузера доверенные служебные поля вроде даты создания. Перед изменением загружать запись и обновлять разрешённые свойства.
11. DTO помогает управлять составом передаваемых данных. Сам факт передачи сущности в Razor не означает автоматическую отправку всех её свойств в браузер; браузер получает то, что реально сформировано в ответе.
12. Реально настроить Serilog: установка пакета сама по себе не включает нужное журналирование.

## Как организовать совместную работу

Оптимальный учебный цикл: я делаю один законченный этап, показываю результат, объясняю ключевые файлы, затем ты повторяешь проверку самостоятельно. После этого переходим к следующему этапу. Так к завершению получится и рабочий проект, и понимание, необходимое для его изменения или защиты.

Я могу писать и изменять код прямо в этой папке, создавать миграции для согласованной учебной базы, разбирать ошибки сборки и запуска, оформлять страницы, проводить проверки и готовить документацию. Вход в личные аккаунты, ввод секретов, системные действия с повышенными правами и решения о реальных расходах могут потребовать твоего участия.

Первый практический этап: уточнить обязательные требования, проверить подключение к существующему SQL Server и создать запускаемый каркас ASP.NET Core MVC. Первая контрольная точка — главная страница открывается локально и проект повторно собирается без ошибок. Полную админку и загрузку файлов подключать после этой проверки.
